Three layers. This file is the authoritative map. When any other

## Layer 1 — Apex Chat (domain model)

The complete type catalog for every element of an agentic LLM system:
chat, participants, models, prompts, memory, content, thinking,
threads, tools, skills, plugins, agents, plans, steps, actions,
guardrails, traces, workspaces, artifacts, resources, capabilities,
sandboxes.

- **Location:** `docs/apex-chat-spec/` (10 files, authoritative)
- **Nature:** pure abstract POJOs. No I/O, no threads, no network, no
  OS calls. Records + sealed interfaces + interfaces. ArchUnit
  enforced.
- **Dependency direction:** common → capability → core → tools →
  agent. Runtime modules import from these; the reverse never happens.
- **What it replaces:** the `kernel-core` records previously planned in
  `PHASES_P1.md` (TenantId, SessionId, CommitId, BlobId, Message
  hierarchy, event hierarchies). Those types now live here. `PHASES_P1.md`
  is deprecated.

If Layer 1 does not have a type for something, the correct action is to
extend Layer 1 (via a new spec file) — not to add the type to Layer 2.

## Layer 2 — Runtime (executing code)

The Java 21 + TypeScript implementation that consumes Layer 1 types and
does the actual work.

- **Module layout:** see `docs/PHASES_P2-P10.md` and the module plan in
  `STANDARDS.md`.
- **Dependencies allowed:** Spring Boot 3.3, LangChain4j, JDBC, Flyway,
  Jackson, Tauri 2.0, React 19. Layer 1 is not allowed these
  dependencies; Layer 2 is.
- **Patterns borrowed (not merged) from prior repos:**
  - `LeanJavallm`: `CancellationToken`, `ProcessTreeTerminator`,
    `ContextCompactor`, `TokenEstimator`, `EphemeralScriptManager`,
    virtual-thread stream drainage. Reimplemented against Layer 1 types.
  - `Agenticplatformsetup`: realpath jail pattern, DAG linter, tiered
    rule line budgets, review-gate pattern. Reimplemented against Layer
    2 module structure.
- **What it is not:** a fork of either prior repo. Those repos are
  reference material only.

## Layer 3 — Prompt stack (build governance)

The 6 stacks that govern how the build agent behaves during Layer 2
construction and evolution.

- **Stacks:** `bootstrap`, `resources`, `roles`, `eval`, `observe`,
  `governance`. See `AGENT_RULES.md`, `PHASES.md`, `STANDARDS.md`,
  `SALVAGE.md`, plus the stack files already at repo root.
- **Loaded per session** via the matrix in `AGENT_RULES.md` §2.
- **Stable:** no changes needed to this layer to accommodate Layer 1.
