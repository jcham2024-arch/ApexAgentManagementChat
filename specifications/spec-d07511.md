## 2. Scope

Add three enforcement gates and prove each one fails on a deliberate
violation. S1.2 is done when all three are green on the clean tree and
each has a documented proof-of-failure.

| Gate | Mechanism | Where |
|---|---|---|
| **G1 — Enterprise ban** | Maven Enforcer | Parent `pom.xml` |
| **G2 — Bytecode purity** | `jdeps` in CI | `.github/workflows/ci.yml` |
| **G3 — Source purity** | ArchUnit test | `apex-chat-common` test sources |

## 3. Changes

### 3.1 Gate G1 — Maven Enforcer

Add to the **parent** `pom.xml`, inside `<build><plugins>` (not
`pluginManagement` — it must run on every module):

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-enforcer-plugin</artifactId>
    <version>3.4.1</version>
    <executions>
        <execution>
            <id>ban-enterprise-in-tier-0</id>
            <phase>validate</phase>
            <goals><goal>enforce</goal></goals>
            <configuration>
                <rules>
                    <bannedDependencies>
                        <excludes>
                            <exclude>org.springframework*</exclude>
                            <exclude>org.springframework.boot*</exclude>
                            <exclude>org.springframework.ai*</exclude>
                            <exclude>com.google.cloud*</exclude>
                            <exclude>com.google.mcp*</exclude>
                            <exclude>org.embabel*</exclude>
                            <exclude>com.fasterxml.jackson*</exclude>
                            <exclude>io.micrometer*</exclude>
                            <exclude>com.zaxxer*</exclude>
                        </excludes>
                        <searchTransitive>true</searchTransitive>
                    </bannedDependencies>
                </rules>
            </configuration>
        </execution>
    </executions>
</plugin>
```

**Why parent, not module:** every module today is Tier 0. When a Tier 1
or Tier 2 module is added in S2+, its `pom.xml` must either inherit a
narrower rule or disable the ban for that module explicitly, with a
comment citing `CONTEXT.md` §4. Do not disable the parent rule for the
whole build.

### 3.2 Gate G2 — `jdeps` in CI

Replace `.github/workflows/ci.yml` with:

```yaml
name: ci
on:
  push:
    branches: ["main", "phase/**"]
  pull_request:
    branches: ["main"]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: "21"
          cache: maven

      - name: Build and test
        run: mvn -B -q test

      - name: Package tier-0 jars
        run: mvn -B -q package -DskipTests

      - name: Gate G2 — jdeps bytecode purity
        run: |
          set -euo pipefail
          for jar in $(find . -path '*/target/*.jar' ! -name '*-sources.jar' ! -name '*-javadoc.jar'); do
            echo "Inspecting $jar"
            if jdeps --ignore-missing-deps --multi-release 21 "$jar" \
               | grep -E 'org\.springframework|org\.embabel|com\.google\.cloud|com\.google\.mcp|com\.fasterxml\.jackson|io\.micrometer|com\.zaxxer'; then
              echo "GATE G2 FAILED: enterprise package in $jar"
              exit 1
            fi
          done
          echo "GATE G2 PASSED"
```

### 3.3 Gate G3 — ArchUnit test

Add ArchUnit as a test dependency to
`apex-chat/apex-chat-common/pom.xml`:

```xml
<dependency>
    <groupId>com.tngtech.archunit</groupId>
    <artifactId>archunit-junit5</artifactId>
    <version>1.3.0</version>
    <scope>test</scope>
</dependency>
```

Create
`apex-chat/apex-chat-common/src/test/java/com/apex/chat/common/CorePurityTest.java`:

```java
package com.apex.chat.common;

import com.tngtech.archunit.core.domain.JavaClasses;
import com.tngtech.archunit.core.importer.ClassFileImporter;
import com.tngtech.archunit.lang.ArchRule;
import org.junit.jupiter.api.Test;

import static com.tngtech.archunit.lang.syntax.ArchRuleDefinition.noClasses;

class CorePurityTest {

    private static final JavaClasses CORE =
            new ClassFileImporter().importPackages("com.apex.chat.common");

    @Test
    void no_enterprise_imports() {
        ArchRule rule = noClasses()
                .should().dependOnClassesThat().resideInAnyPackage(
                        "org.springframework..",
                        "org.embabel..",
                        "com.google.cloud..",
                        "com.google.mcp..",
                        "com.fasterxml.jackson..",
                        "io.micrometer..",
                        "com.zaxxer..");
        rule.check(CORE);
    }

    @Test
    void no_platform_io() {
        ArchRule rule = noClasses()
                .should().dependOnClassesThat().resideInAnyPackage(
                        "java.io..",
                        "java.nio.file..",
                        "java.net..",
                        "java.lang.reflect..");
        rule.check(CORE);
    }

    @Test
    void no_executors() {
        ArchRule rule = noClasses()
                .should().dependOnClassesThat()
                .haveFullyQualifiedName("java.util.concurrent.Executors");
        rule.check(CORE);
    }
}
```

**Why the classes are imported once in a static field:** ArchUnit class
import is the expensive step; importing once per test class halves the
wall-clock. The rule definitions are the cheap part.

## 4. Gate proofs (mandatory)

Every gate must be proven to **fail on a deliberate violation**. Do each
proof on the `phase/s1.2-gates` branch, capture the failure output, then
revert the violation before the final commit.

Create `docs/S1-GATE-PROOFS.md` with three sections, each containing:

1. The violation you introduced
2. The command you ran
3. The failure output (verbatim, in a fenced block)
4. The revert you performed

### Proof G1

Temporarily add to `apex-chat/apex-chat-common/pom.xml`:

```xml
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-core</artifactId>
    <version>6.1.0</version>
</dependency>
```

Run `mvn -B validate`. Capture the Enforcer failure. Remove the
dependency. Rerun `mvn -B validate` — must pass.

### Proof G2

Temporarily add a class in `apex-chat-common`:

```java
package com.apex.chat.common.leak;
import org.springframework.core.io.ClassPathResource;
final class LeakProbe { ClassPathResource r; }
```

Run `mvn -B package -DskipTests` and the `jdeps` loop from §3.2.
Capture the gate failure. Delete the class. Rerun — must pass.

### Proof G3

Same temporary class as Proof G2. Run `mvn -B test`. Capture the
ArchUnit failure. Delete the class. Rerun — must pass.

**Order matters:** Proof G2 will not reach the `jdeps` step if Proof
G3's ArchUnit test fails first in the same `mvn test` run. So do G3
first, then G2, then G1, each with its own clean/revert cycle.

## 5. Exit criteria

A. `mvn -B validate` passes with the Enforcer configured.
B. `mvn -B test` passes with the ArchUnit tests in place.
C. The `jdeps` CI step passes on the clean tree.
D. `docs/S1-GATE-PROOFS.md` exists and contains three documented
   proofs, one per gate.
E. No files other than the ones in §3 exist or were modified.
F. No enterprise dependency is present in the tree at commit time.
