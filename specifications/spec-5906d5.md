# Android LLM Agent Harness — Implementation Spec

> **Audience:** an agentic coding LLM implementing this in an existing Android app (Kotlin, minSdk 26+, targetSdk 35).
> **Goal:** lowest-latency, highest-reliability communication between an agent loop on Android, a cloud LLM API, and remote/local MCP tool servers.
> **Non-negotiable constraints:** survives Wi-Fi↔cellular handover, survives backgrounding, streams tokens without UI jank, never re-handshakes on every turn.

---

## 0. Architecture (implement exactly this)

```
                    ┌───────────────────────────────────────┐
                    │        AgentLoop (CoroutineWorker)     │
                    │   plan → call tool → observe → repeat  │
                    └───────┬───────────────────┬───────────┘
                            │                   │
             SSE (HTTP/2)   │                   │  Streamable HTTP (HTTP/2)
                            ▼                   ▼
                    ┌───────────────┐   ┌───────────────────────┐
                    │ Cloud LLM API │   │  MCP Servers (remote)  │
                    └───────────────┘   └───────────────────────┘
                            │                   │
                            └─────────┬─────────┘
                                      ▼
                        ┌──────────────────────────┐
                        │  ONE shared OkHttpClient │
                        │  engine = Cronet (HTTP/3)│
                        │  HTTP/2 pool, warm socks │
                        └──────────────────────────┘
                                      │
                        ┌─────────────┴──────────────┐
                        │ Local on-device tools       │
                        │ (in-process MCP via stdio-  │
                        │  style direct calls, 0 net) │
                        └─────────────────────────────┘
```

**Rule:** exactly **one** `OkHttpClient` (and one `CronetEngine`) exists in the app. Both the LLM SSE stream and all MCP HTTP traffic go through it. Do not create per-call clients.

## 3. Step 1 — Network engine (Cronet + one shared OkHttpClient)

`core/net/CronetEngineFactory.kt`:

```kotlin
object CronetEngineFactory {
    @Volatile private var engine: CronetEngine? = null

    fun get(context: Context): CronetEngine = engine ?: synchronized(this) {
        engine ?: build(context.applicationContext).also { engine = it }
    }

    private fun build(ctx: Context): CronetEngine =
        CronetEngine.Builder(ctx)
            .enableQuic(true)
            .enableHttp2(true)
            .enableBrotli(true)
            .enableHttpCache(CronetEngine.Builder.HTTP_CACHE_DISK_NO_HTTP, 10L * 1024 * 1024)
            // Tune H2/QUIC: large streams must not stall behind small RPCs
            .setExperimentalOptions("""
                {
                  "http2": { "max_concurrent_streams": 100 },
                  "quic": {
                    "max_server_configs_stored_in_properties": 20,
                    "idle_connection_timeout_seconds": 300,
                    "close_sessions_on_ip_change": false,
                    "goaway_sessions_on_ip_change": false
                  }
                }
            """.trimIndent())
            .build()
}
```

`core/net/Http.kt`:

```kotlin
object Http {
    @Volatile private var client: OkHttpClient? = null

    fun get(context: Context): OkHttpClient = client ?: synchronized(this) {
        client ?: build(context.applicationContext).also { client = it }
    }

    private fun build(ctx: Context): OkHttpClient {
        val cronet = CronetEngineFactory.get(ctx)
        return OkHttpClient.Builder()
            // Cronet interceptor: routes every call through the Chromium stack
            .addInterceptor(CronetInterceptor(cronet))
            .connectionPool(ConnectionPool(maxIdleConnections = 8, keepAliveDuration = 65, TimeUnit.SECONDS))
            .protocols(listOf(Protocol.HTTP_2, Protocol.HTTP_1_1))
            .connectTimeout(10, TimeUnit.SECONDS)
            .readTimeout(0, TimeUnit.SECONDS)      // SSE: no read timeout on the stream body
            .callTimeout(0, TimeUnit.SECONDS)      // let the agent loop own cancellation
            .retryOnConnectionFailure(true)
            .build()
    }

    /** Fire-and-forget DNS warmup at app start — no-op on failure. */
    fun prefetchDns(hosts: List<String>) {
        kotlin.concurrent.thread(isDaemon = true) {
            hosts.forEach { runCatching { InetAddress.getAllByName(it) } }
        }
    }
}
```

Call `Http.prefetchDns(listOf(modelApiHost, mcpServerHost))` in `Application.onCreate()`.

**Do not** wrap the SSE call body in `withTimeout`; cancel the coroutine instead.

## 4. Step 2 — SSE streaming client

`core/net/SseClient.kt`:

```kotlin
data class SseEvent(val event: String, val data: String)

class SseClient(private val client: OkHttpClient) {

    fun post(url: String, jsonBody: String, headers: Map<String, String> = emptyMap()): Flow<SseEvent> =
        flow {
            val req = Request.Builder()
                .url(url)
                .header("Accept", "text/event-stream")
                .header("Cache-Control", "no-cache")
                .apply { headers.forEach { (k, v) -> header(k, v) } }
                .post(jsonBody.toRequestBody("application/json".toMediaType()))
                .build()

            client.newCall(req).execute().use { resp ->
                if (!resp.isSuccessful) error("SSE HTTP ${resp.code}: ${resp.body?.string()?.take(512)}")
                val src = resp.body!!.source()
                var event = "message"
                val data = StringBuilder()
                while (currentCoroutineContext().isActive) {
                    val line = src.readUtf8Line() ?: break
                    when {
                        line.isEmpty() -> {
                            if (data.isNotEmpty()) {
                                emit(SseEvent(event, data.toString().trimEnd('\n')))
                                data.clear()
                            }
                            event = "message"
                        }
                        line.startsWith(":") -> Unit                    // keepalive comment
                        line.startsWith("event:") -> event = line.substring(6).trim()
                        line.startsWith("data:") ->
                            data.append(line.substring(5).trimStart()).append('\n')
                        else -> Unit                                     // id:, retry: ignored
                    }
                }
                // flush trailing event if server closed without blank line
                if (data.isNotEmpty()) emit(SseEvent(event, data.toString().trimEnd('\n')))
            }
        }.flowOn(Dispatchers.IO)
}
```

**Parsing tokens** (model-adapter layer, not shown): decode each `data` as JSON; on OpenAI-style payloads extract `choices[0].delta.content`; treat `data: [DONE]` as end-of-stream; accumulate `tool_calls` deltas into complete call objects before dispatch.

## 5. Step 3 — MCP client over Streamable HTTP, sharing the OkHttp pool

The MCP Kotlin SDK is Ktor-based. **Reuse the same OkHttpClient** by injecting it into Ktor's OkHttp engine — this is what makes MCP calls multiplex over the same HTTP/2/3 connection as the model stream.

`core/mcp/McpClientProvider.kt`:

```kotlin
class McpClientProvider(private val appContext: Context) {

    private val ok = Http.get(appContext)

    private val ktor = HttpClient(OkHttp) {
        engine {
            preconfigured = ok                 // ← the whole point: shared connection pool
            config { retryOnConnectionFailure(true) }
        }
        install(ContentNegotiation) { json() }
    }

    private val clients = mutableMapOf<String, Client>()

    /** Connect to a remote MCP server using Streamable HTTP. */
    suspend fun clientFor(serverUrl: String): Client = clients.getOrPut(serverUrl) {
        val transport = StreamableHttpClientTransport(
            client = ktor,
            url = serverUrl,
            // Auth: pass bearer token via requestBuilder if server requires it
        )
        Client(
            clientInfo = Implementation(name = "android-agent", version = "1.0.0"),
            options = ClientOptions(),
            transport = transport
        ).also { it.connect() }
    }

    suspend fun listTools(serverUrl: String): List<Tool> =
        clientFor(serverUrl).listTools().tools

    suspend fun callTool(serverUrl: String, name: String, args: JsonObject): CallToolResult =
        clientFor(serverUrl).callTool(
            CallToolRequest(name = name, arguments = args)
        )

    suspend fun closeAll() {
        clients.values.forEach { runCatching { it.close() } }
        clients.clear()
    }
}
```

**Local (on-device) tools:** do **not** spin up an HTTP MCP server. Expose them as a direct `Map<String, suspend (JsonObject) -> JsonElement>` registry inside the agent loop and register the same names as the cloud model's tool schema. Zero network hop, zero serialization overhead beyond the tool-call JSON. Only use stdio/child-process MCP for bundled third-party servers that already ship as MCP binaries.

## 6. Step 4 — Agent loop: WorkManager chain + Foreground Service

### 6.1 State model (checkpointable)

`agent/AgentStateStore.kt` — persist to DataStore as JSON:

```kotlin
@Serializable
data class AgentState(
    val sessionId: String,
    val turnIndex: Int = 0,
    val messages: List<AgentMessage> = emptyList(),
    val pendingToolCall: ToolCall? = null,
    val status: Status = Status.RUNNING,
    val createdAtEpochMs: Long,
    val idempotencyKeys: List<String> = emptyList()   // one per tool call
) { enum class Status { RUNNING, WAITING_NETWORK, DONE, FAILED } }
```

Every transition (`after model response`, `before tool call`, `after tool result`) writes a checkpoint. **A killed worker must be resumable from the last checkpoint.**

### 6.2 One iteration = one CoroutineWorker

`agent/AgentStepWorker.kt`:

```kotlin
class AgentStepWorker(ctx: Context, params: WorkerParameters) :
    CoroutineWorker(ctx, params) {

    override suspend fun doWork(): Result = withContext(Dispatchers.IO) {
        val store = AgentStateStore(applicationContext)
        var state = store.load(AgentState::class.java) ?: return Result.failure()

        if (!NetworkMonitor.isOnline(applicationContext)) {
            return Result.retry()                       // WorkManager backoff
        }

        try {
            state = runOneIteration(state, store)       // model call → tool calls → checkpoint
            store.save(state)

            if (state.status == AgentState.Status.DONE) {
                Result.success()
            } else {
                enqueueNextStep(applicationContext)     // chain the next iteration
                Result.success()
            }
        } catch (e: IOException) {
            Result.retry()                              // network flake: WorkManager retries
        } catch (e: CancellationException) {
            throw e
        } catch (e: Exception) {
            store.save(state.copy(status = AgentState.Status.FAILED))
            Result.failure()
        }
    }

    companion object {
        const val WORK_NAME = "agent-step"

        fun enqueueNextStep(ctx: Context) {
            val req = OneTimeWorkRequestBuilder<AgentStepWorker>()
                .setConstraints(
                    Constraints.Builder()
                        .setRequiredNetworkType(NetworkType.CONNECTED)
                        .build()
                )
                .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 5, TimeUnit.SECONDS)
                .build()
            WorkManager.getInstance(ctx)
                .enqueueUniqueWork(WORK_NAME, ExistingWorkPolicy.APPEND_OR_REPLACE, req)
        }
    }
}
```

### 6.3 `runOneIteration` contract

```
1. If state.pendingToolCall != null:      → execute tool (local or MCP), append result, clear pending, save
2. Else:                                   → POST messages to LLM, stream SSE
     - append assistant deltas to a buffer; on tool_call delta complete → set pendingToolCall, save, return
     - on finish_reason=stop → status = DONE
3. Enforce max iterations (e.g. 12) and a wall-clock budget (e.g. 120 s) → status = FAILED
```

### 6.4 Foreground Service for active sessions

`agent/AgentForegroundService.kt`:

```kotlin
class AgentForegroundService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        val notification = buildOngoingNotification()      // "Agent working…" with Stop action
        if (Build.VERSION.SDK_INT >= 34) {
            startForeground(ID, notification, ServiceInfo.FOREGROUND_SERVICE_TYPE_DATA_SYNC)
        } else {
            startForeground(ID, notification)
        }
        AgentStepWorker.enqueueNextStep(this)
        return START_NOT_STICKY
    }
    override fun onBind(intent: Intent?) = null
}
```

Manifest:

```xml
<service android:name=".agent.AgentForegroundService"
         android:foregroundServiceType="dataSync"
         android:exported="false"/>
```

**Rule:** start the FGS when the user submits a prompt; stop it when `AgentState.status != RUNNING`. WorkManager drives the actual iterations — the service only prevents process death while the loop is hot.

## 7. Step 5 — Token streaming into Compose without jank

Never emit one state update per token at 50–80 tok/s.

`ui/StreamBatching.kt`:

```kotlin
/** Coalesces stream elements into time-windowed batches, preserving order and every element. */
fun <T> Flow<T>.batchByTime(windowMs: Long): Flow<List<T>> = channelFlow {
    val src = this@batchByTime.produceIn(this)
    val buf = ArrayList<T>()
    while (true) {
        val first = src.receiveCatching().getOrNull() ?: break
        buf += first
        val deadline = SystemClock.elapsedRealtime() + windowMs
        while (true) {
            val remaining = deadline - SystemClock.elapsedRealtime()
            if (remaining <= 0) break
            val next = withTimeoutOrNull(remaining) { src.receiveCatching().getOrNull() } ?: break
            buf += next
        }
        emit(buf.toList())
        buf.clear()
    }
    if (buf.isNotEmpty()) emit(buf.toList())
}
```

Usage in the ViewModel:

```kotlin
sseClient.post(url, body, headers)
    .filter { it.data != "[DONE]" }
    .map { parseToken(it.data) }
    .batchByTime(48)                                  // ≈3 frames @60fps
    .onEach { tokens -> uiState.update { s -> s.copy(text = s.text + tokens.joinToString("")) } }
    .launchIn(viewModelScope)
```

Compose side: `Text(uiState.text)` with a stable `remember`-ed modifier. Do not use `AnnotatedString` rebuilds inside the text composable for the whole buffer — keep the growing string as a single `State<String>`.

## 8. Step 6 — Network awareness (adaptive agent behavior)

`core/net/NetworkMonitor.kt`:

```kotlin
data class NetState(val online: Boolean, val isWifi: Boolean, val downKbps: Int, val validated: Boolean)

object NetworkMonitor {
    fun isOnline(ctx: Context): Boolean {
        val cm = ctx.getSystemService(ConnectivityManager::class.java)
        return cm.activeNetwork?.let { cm.getNetworkCapabilities(it) }?.let {
            it.hasCapability(NetworkCapabilities.NET_CAPABILITY_INTERNET) &&
            it.hasCapability(NetworkCapabilities.NET_CAPABILITY_VALIDATED)
        } == true
    }

    fun states(ctx: Context): Flow<NetState> = callbackFlow {
        val cm = ctx.getSystemService(ConnectivityManager::class.java)
        val cb = object : ConnectivityManager.NetworkCallback() {
            override fun onCapabilitiesChanged(n: Network, caps: NetworkCapabilities) {
                trySend(NetState(
                    online = caps.hasCapability(NetworkCapabilities.NET_CAPABILITY_VALIDATED),
                    isWifi = caps.hasTransport(NetworkCapabilities.TRANSPORT_WIFI),
                    downKbps = caps.linkDownstreamBandwidthKbps,
                    validated = caps.hasCapability(NetworkCapabilities.NET_CAPABILITY_VALIDATED)
                ))
            }
            override fun onLost(n: Network) { trySend(NetState(false, false, 0, false)) }
        }
        cm.registerDefaultNetworkCallback(cb)
        awaitClose { cm.unregisterNetworkCallback(cb) }
    }.conflate()
}
```

**Policy the agent loop must apply:**
- `validated == false` → do not start a model call; return `Result.retry()`.
- `!isWifi && downKbps < 500` → cap parallel MCP tool calls to **1**, disable speculative prefetch, prefer local tools over remote.
- Wi-Fi→cellular transition → nothing to do (Cronet migrates the QUIC connection); **do not** recreate the client, **do not** cancel and retry in-flight streams.

## 9. Step 7 — Hybrid routing (do this if a local model is available)

Order of resolution for every user request / tool-call decision:

```
1. Is there a matching local tool?              → execute locally (0 ms network)
2. Is the intent classifiable by a tiny model?  → route directly, skip cloud
3. Otherwise                                    → cloud LLM with compressed context
```

- **Compression before cloud:** run a local BIO/keyword extractor (ML Kit or a small LiteRT model) over retrieved context; send only tagged spans + a prompt anchor. Target ≥40 % token reduction.
- **Firebase AI Logic / LiteRT-LM hybrid inference** may be used as the routing backend when available; fall back to the cloud endpoint on `UNAVAILABLE`.
- The router must be a pure function `route(request, netState, localTools) -> Route` so it is unit-testable without network.

## 10. Step 8 — Resilience rules (mandatory)

| Concern | Implementation |
|---|---|
| **Retries** | `Result.retry()` from the worker; exponential backoff with 5 s base, WorkManager caps it. Never retry a non-idempotent tool call without its key. |
| **Idempotency** | Generate a UUID per tool call; persist in `state.idempotencyKeys`; send as `Idempotency-Key` header on MCP calls that mutate state. |
| **Tool-call timeout** | 30 s per MCP call via `withTimeout`; on timeout, append a structured error result and continue the loop — do not fail the turn. |
| **Max loop depth** | 12 iterations. On exceed: return a partial answer + `status = FAILED` with reason. |
| **Cancellation** | User "Stop" → `WorkManager.cancelUniqueWork("agent-step")` + `stopService` + cancel the ViewModel scope; propagate to the MCP client via `CoroutineScope.cancel()`. |
| **Cold-start latency** | `Http.prefetchDns(...)` in `Application.onCreate()`; keep the client process-warm by starting the FGS only when a turn begins (do not keep it running idle). |
| **Keep-alive** | Server keepalive comments (`: ping`) are ignored by the parser and prevent proxies from closing the SSE stream. Client pool keepalive = 65 s. |

## 11. Latency budget (targets to verify)

| Phase | Target | Instrumentation |
|---|---|---|
| DNS + TCP + TLS (warm) | < 50 ms | OkHttp `EventListener` |
| First token (TTFT) | provider-bound | timestamp at first `emit` in `SseClient` |
| Inter-token | provider-bound; no client-side stalls | watch for gaps > 500 ms (indicates missing keepalive) |
| MCP tool round-trip (remote) | < 800 ms p50 | `EventListener` on the same client |
| Local tool call | < 20 ms | same |
| Compose frame drops during stream | 0 | Macrobenchmark `FrameTimingMetric` |

**Rule:** a serialization-format change (JSON vs protobuf) is not a lever here. Inference time dominates. Spend effort on connection reuse, stream stability, and eliminating needless round-trips.

## 12. Anti-patterns — do not implement

- ❌ Creating a new `OkHttpClient` / `CronetEngine` per request or per session.
- ❌ Using WebSocket for LLM token streaming (dedicated socket, no multiplexing, battery cost).
- ❌ Running the MCP HTTP server on the device just to expose local tools.
- ❌ Emitting a Compose state update per token.
- ❌ Wrapping the SSE body in `readTimeout`/`callTimeout` — cancel the coroutine instead.
- ❌ Catching `IOException` inside the loop and swallowing it — let the worker `retry()`.
- ❌ Recreating the MCP `Client` on every turn — cache per server URL.
- ❌ Blocking `onStartCommand` / `onCreate` with network work — enqueue the worker.

## 13. Definition of done — verification checklist

The implementation is complete when **all** of these pass:

- [ ] `grep -r "OkHttpClient.Builder" app/src` returns **exactly one** occurrence (in `Http.kt`).
- [ ] `grep -r "CronetEngine.Builder" app/src` returns **exactly one** occurrence (in `CronetEngineFactory.kt`).
- [ ] An OkHttp `EventListener` in a debug build shows `protocol=h2` or `h3` for both the LLM endpoint and every MCP endpoint.
- [ ] Airplane-mode toggle during an in-flight stream: stream resumes (Cronet migration + retry) or the worker returns `Result.retry()` and resumes on reconnect — **no crash, no lost state**.
- [ ] Process kill (ADB `am kill`) mid-tool-call → app restarts → agent resumes from the persisted checkpoint.
- [ ] Remote MCP tool call count per turn is visible in logs; parallel calls are capped to 1 on degraded cellular.
- [ ] Macrobenchmark streaming a 500-token response reports **zero** dropped frames with `batchByTime(48)`; using per-token emission reports >0 (control test).
- [ ] A 12-iteration loop exits with `status = FAILED` and a partial answer, not an infinite hang.
- [ ] `prefetchDns` appears in `Application.onCreate()` and warm-start TTFT is measurably lower than cold-start in a repeated-run benchmark.
- [ ] Unit tests: `SseClient` parses multi-line `data:`, ignores `: comment`, handles `[DONE]`, and flushes a trailing event on abrupt close.
- [ ] Unit test: `batchByTime` preserves every element and order under randomized emission timing.

## 14. Optional follow-ons (only after §13 passes)

1. **Cronet via gRPC** — if the MCP servers expose gRPC, swap `StreamableHttpClientTransport` for a Cronet-backed gRPC channel. Gains: binary framing, lower per-message overhead. Only worth it at high tool-call frequency.
2. **AppFunctions / Jetpack** — expose app actions as MCP tools through Google's platform integration so the cloud model can call them without bespoke schema glue.
3. **On-device model escalation** — LiteRT-LM or Gemini Nano for intent classification and context compression upstream of the cloud call.
