**.agents/rules/tool-selection.md**
```markdown
# Tool Selection

One tool per job. Do not call two tools for the same gap in one turn.

| Need | Use | Never use |
|---|---|---|
| Current facts from the web | Exa (deep) | Context7, memory |
| A library's API | Context7 | Exa |
| A decision made earlier in this project | Mem0 | Exa |
| A page that requires clicking or login | Playwright | Exa |
| A file in the wiki | MCPVault | filesystem MCP |
| A file in scratch/review/output | filesystem MCP | MCPVault |
| Open a PR or read an issue | GitHub MCP | Playwright |
| Enforce plan/TDD/debug order | Superpowers skill | ad-hoc reasoning |

If a tool errors twice, stop and report. Do not chain fallbacks
silently; the operator must know which capability is degraded.
```

**.agents/skills/web-search/SKILL.md**
```markdown
---
name: web-search
description: Use when the task needs facts that may have changed since training, or sources outside the repo and wiki.
---

# Web Search

## When to use
- A claim needs a source dated after the model's training cutoff.
- The answer is not in the repo, the wiki, or memory.
- You need to compare current options (pricing, versions, benchmarks).

## Tool
Exa MCP, `deep` mode. One call, then read the results before a second
call. Do not fan out five searches for one question.

## Process
1. State the question in one sentence.
2. Call Exa once with the question, not with keywords.
3. Read the top results. If two disagree, note both.
4. Cite every fact with URL and date.
5. Mark anything you could not verify `[unverified]`.

## Output
A short answer with inline citations. No preamble.

## Failure modes
- Exa rate-limited: report and stop. Do not silently switch to a
  different search API; that changes the evidence base.
- Results are stale: say so and give the date of the newest source.
```

**.agents/skills/docs-lookup/SKILL.md**
```markdown
---
name: docs-lookup
description: Use when writing code against a library or API whose current signature matters.
---

# Docs Lookup

## When to use
- Before importing or calling a library you have not used in this
  session.
- When a type error suggests the API changed.
- When the design names a function whose signature you are guessing.

## Tool
Context7 MCP. Query with the library name and the specific symbol.

## Process
1. Name the library and the symbol.
2. Fetch the version-pinned docs.
3. Quote the signature and the version.
4. If the docs do not cover the symbol, say so — do not infer from
   memory.

## Output
The signature, the version, and a one-line usage example.

## Failure modes
- Library not indexed: say so and fall back to web search, explicitly.
- Docs conflict with the installed version: trust the installed version,
  note the drift.
```

```markdown

name: knowledge-base
description: Use when the answer may already exist in the project wiki or prior notes.
---

# Knowledge Base

## When to use
- Before researching anything that this project may have already
  decided.
- When a term is defined in `reference/` or the wiki.
- When the task references a prior proposal or review.

## Tool
MCPVault, pointed at `$VAULT_PATH`. BM25 search; read only the top
three hits before deciding to widen.

## Process
1. Search with the exact term from the task.
2. Read the top three notes.
3. If a note answers the question, cite the note path.
4. If nothing matches, say "no prior note" and hand off to research.

## Output
The note path and the one-line answer.

## Failure modes
- Vault path unset: stop and report. Do not guess a path.
- Note is stale: cite it and flag the date.
```

**.agents/skills/memory/SKILL.md**
```markdown
---
name: memory
description: Use to recall or record a decision, preference, or constraint that must survive across sessions.
---

# Memory

## When to use
- The operator states a preference ("always use records", "no
  Spring in P1").
- A design decision is made and will constrain later phases.
- A failure repeats and the fix should be remembered.

## Tool
Mem0 MCP. One write per fact; one read per recall.

## Process
1. Before asking the operator something that may have been decided,
   search memory.
2. When a durable decision is made, write it as one sentence with the
   date and the phase.
3. Never store secrets, tokens, or personal data.

## Output
On recall: the fact and its date. On write: confirmation of the one
sentence stored.

## Failure modes
- Memory returns a conflict: report both and ask which is current.
- Write fails: continue the task, note that memory is degraded.
```

**.agents/skills/browser/SKILL.md**
```markdown
---
name: browser
description: Use when a page requires navigation, clicking, login, or JavaScript that fetch cannot handle.
---

# Browser

## When to use
- The target page renders only with JavaScript.
- A task needs a click, a form fill, or a logged-in session.
- A screenshot is needed for verification.

## Tool
Playwright MCP. Prefer `navigate` → `snapshot` → act on selectors from
the snapshot, not on guessed coordinates.

## Process
1. Navigate.
2. Take a snapshot; read the accessibility tree.
3. Act on named elements only.
4. Verify the result with a second snapshot.
5. Close the page.

## Output
The action taken, the observed result, and the final URL.

## Failure modes
- Selector not found: re-snapshot, do not retry the same click.
- Login wall: stop and ask the operator; never enter credentials from
  memory.
```

**.agents/skills/repo-ops/SKILL.md**
```markdown
---
name: repo-ops
description: Use for pull requests, issues, reviews, and branch operations on the GitHub remote.
---

# Repo Ops

## When to use
- Opening or updating a pull request.
- Reading an issue or review comment.
- Checking CI status on a branch.

## Tool
GitHub MCP. Never use Playwright for GitHub; the API is the surface.

## Process
1. Read before write: fetch the PR or issue first.
2. State the branch and the base in every PR action.
3. Never force-push. Never merge without a green check and a human
   approval.
4. Quote the CI conclusion, not a paraphrase.

## Output
The PR or issue number, the action, and the resulting state.

## Failure modes
- Token lacks scope: report the missing scope; do not retry with a
  broader token.
- CI red: report the failing job and log excerpt; do not merge.
```

**scripts/install-resources.sh**
```bash
#!/usr/bin/env bash
# Installs the capability stack. Dry-run by default.
# Usage: ./scripts/install-resources.sh --apply
set -euo pipefail

APPLY=0
[[ "${1:-}" == "--apply" ]] && APPLY=1

require() {
  command -v "$1" >/dev/null 2>&1 || { echo "missing: $1"; exit 1; }
}
require node
require npx

run() {
  echo "+ $*"
  if [[ "$APPLY" -eq 1 ]]; then "$@"; fi
}

echo "== skills =="
run npx -y skills add obra/superpowers
run npx -y skills add anthropics/skills

echo "== mcp servers (verify package names in RESOURCES.md first) =="
run npx -y @modelcontextprotocol/server-filesystem --help
run npx -y @modelcontextprotocol/server-github --help
run npx -y @upstash/context7-mcp --help
run npx -y @playwright/mcp@latest --help
run npx -y exa-mcp-server --help
run npx -y mem0-mcp --help
run npx -y mcpvault --help

echo "== env =="
for v in EXA_API_KEY GITHUB_PAT MEM0_API_KEY VAULT_PATH; do
  if [[ -z "${!v:-}" ]]; then echo "unset: $v"; else echo "ok: $v"; fi
done

echo
if [[ "$APPLY" -eq 0 ]]; then
  echo "dry run complete. re-run with --apply to install."
fi
```

**scripts/healthcheck-resources.sh**
```bash
#!/usr/bin/env bash
set -uo pipefail
fail=0

check() {
  local name="$1"; shift
  if "$@" >/dev/null 2>&1; then echo "ok   $name"; else echo "FAIL $name"; fail=1; fi
}

check "node"        command -v node
check "npx"         command -v npx
check "jq"          command -v jq
check "mcp.json"    jq empty .mcp.json
check "vault path"  test -d "${VAULT_PATH:-/nonexistent}"
check "exa key"     test -n "${EXA_API_KEY:-}"
check "github pat"  test -n "${GITHUB_PAT:-}"
check "mem0 key"    test -n "${MEM0_API_KEY:-}"
check "playwright"  npx -y @playwright/mcp@latest --help
check "context7"    npx -y @upstash/context7-mcp --help

exit "$fail"
```
